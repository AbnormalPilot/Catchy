# Catchy

Native macOS menu bar app (SwiftUI + AppKit, macOS 26+) that turns copied text or a captured
screen region into a Calendar event using Apple's on-device Foundation Models. Nothing leaves the Mac.

Goal: a 1–3 minute demo where a messy flyer becomes a correct calendar event that shows up on iPhone.

## Build & run
- Project is generated by XcodeGen from `project.yml`. After adding/removing files or changing
  settings: `xcodegen generate`. Commit both `project.yml` and `Catchy.xcodeproj`.
- Build: `xcodebuild -project Catchy.xcodeproj -scheme Catchy -configuration Debug -derivedDataPath build -allowProvisioningUpdates build`
- Run: `pkill -x Catchy; open build/Build/Products/Debug/Catchy.app`
- Quick clipboard test: `printf 'SPRING FLING\nthis saturday 7-10pm\nRiverside Park' | pbcopy` → popover opens.
- Signed with the local Apple Development identity (team 56T7M6558P). Keep a stable signature:
  ad-hoc signing changes every build and TCC (Screen Recording, Calendars) forgets the grant.

## Architecture
- `App/CatchyApp.swift` — entry point + AppDelegate wiring (status item, clipboard watcher).
- `App/StatusItemController.swift` — `NSStatusItem` + `NSPopover` (not `MenuBarExtra`: it can't be opened from code).
- `App/AppState.swift` — `@Observable` phase machine: idle → reading → review → saved / nothingFound / failed.
- `Services/ClipboardWatcher.swift` — polls `changeCount`; uses `detectedPatterns(for: [\.calendarEvents])`
  so the contents are only read when the system says there's an event. Skips concealed/transient types.
- `Services/EventExtractor.swift` — `@Generable GeneratedEvent`, greedy sampling, fresh session per catch,
  prewarmed. Falls back to `DateHints` when Apple Intelligence is unavailable.
- `Services/DateHints.swift` — `NSDataDetector` dates/address/link; resolved dates are fed to the model as anchors.
- `Services/CalendarService.swift` — EventKit access + save; prefers an iCloud calendar so events reach iPhone/Watch.
- `Services/GlobalHotKey.swift` — Carbon `RegisterEventHotKey` (no Accessibility permission needed).
- `Services/ScreenCapture.swift` — Screen Recording permission + `SCScreenshotManager.captureImage(in:)` + Vision `RecognizeTextRequest`.
- `UI/RegionSelector.swift` — dimmed overlay windows on every screen for drag-to-select.
- `Services/TimeZones.swift` — "ET"/"PST"/"GMT+1"/"London" → TimeZone.
- `Services/ServiceProvider.swift` — right-click › Services › Catch with Catchy (`NSServices` in project.yml).
- `UI/CatchListView.swift` — several catches as a checklist; `EventCardView` edits one (event or task).
- `UI/` — SwiftUI popover views; Liquid Glass via `.glass` / `.glassProminent` button styles.

## Conventions
- Swift 6, default actor isolation = MainActor, approachable concurrency. Calling a nonisolated SDK async
  API on a non-Sendable AppKit object from MainActor errors ("sending ... risks data races"): do it in a
  `nonisolated static` helper that fetches the object itself.
- Every permission state needs visible UI: not determined → system prompt on first use; denied → banner
  with a button to the right System Settings pane.
- Keep it small. No settings screens; remember the last-used choice in UserDefaults instead.

## Lessons
- Apple Intelligence may be off on the dev Mac: `SystemLanguageModel.default.availability` is then
  `.appleIntelligenceNotEnabled` and only the `DateHints` fallback runs. Turn it on in System Settings ›
  Apple Intelligence & Siri to test the real model.
- `NSPasteboard.detectedPatterns(for: [\.calendarEvents])` (macOS 15.4+) flags casual text like
  "dinner at mine fri 8?" and flyer text; it's a reliable gate.
- `SCScreenshotManager.captureImage(in:)` takes a rect in global *display* space (top-left origin), not
  AppKit's bottom-left screen space; flip Y against the primary screen's height.
- On a notched MacBook with a crowded menu bar the status item can be hidden; the popover then anchors oddly.
- `NSDataDetector` splits "Sat, Oct 24 • 4pm - 9pm" into a date-only and a time-only match (the time
  resolves to *today*). `DateHints` merges them; strip titles using the raw phrases, not the merged one.
- User wants the hotkey as ⌥⌘C (note: shadows Finder's "Copy as Pathname" while Catchy runs).
- Screen Recording can't be granted from code after the first prompt, and a grant only applies after relaunch;
  the popover has "Allow Access" (prompt/opens Settings) and "Reopen Catchy".
- Test helpers that compile app files standalone: `swiftc` with a `main.swift` (top-level code) plus the
  files; don't pass `-parse-as-library`.
- With an auto-hiding menu bar the status item's window sits *above* the screen (`window.screen == nil`)
  and a popover shown from it lands in the corner. `StatusItemController` then anchors to an invisible
  window at the icon's x at the top edge. Always test auto-popups with the menu bar hidden.
- Auto-popups (copy/hotkey) need `NSApp.activate(ignoringOtherApps: true)`; plain `activate()` is refused
  under cooperative activation and the card shows dimmed/inactive.
- Don't use `onChange(of: draft.start)` to drag the end along: it also fires when a new catch replaces
  the draft. Use a custom Binding so only user edits shift the end.
- The user works on this Mac while you test; auto-popup tests steal focus. Keep live UI tests few and short.
- `NSDataDetector` already converts zoned times ("3:00 pm ET") and exposes `match.timeZone`. The model is
  told to write times *as written* plus a `timeZone`; `EventExtractor` builds the date in that zone.
- Keep `Model/`, `DateHints`, `TimeZones` free of AppKit/EventKit so they compile standalone in a
  `swiftc` harness (fast checks without launching the app).
- Verify the Services menu without clicking: `/System/Library/CoreServices/pbs -update`, then a script calling
  `NSPerformService("Catch with Catchy", pasteboard)`.
- Presenting the popover in `applicationDidFinishLaunching` does nothing; the status item isn't placed yet.
  Delay ~0.8 s (first-run welcome does this).
- The sandboxed app's defaults live in `~/Library/Containers/app.catchy.Catchy/Data/Library/Preferences/`.
- "Apple Intelligence is off" on this Mac was `appleIntelligenceNotEnabled` (M4, macOS 26.2, en-US, eligible):
  a Settings toggle, not a hardware limit. Check with a one-line script printing `SystemLanguageModel.default.availability`.
- Neither `NSDataDetector` nor the pasteboard's `detectedPatterns`/`detectedValues` understand relative times
  ("meet with sujan 20 mins", "in 2 hours", "for 15 mins"). `DateHints.relativeTimes` handles them, and the
  clipboard gate also lets chat-length text (≤280 chars) through when it has one. README's privacy note says so.
- Read lengths in context (user correction): only "in 20 mins" is a start time. A bare "20 mins" or "for 20 mins"
  is how long it lasts; with no start given, start at the next 5-minute mark. The model prompt says the same.
- `Calendar.date(bySetting: .second, value: 0, of:)` returns the *next* matching minute, not a truncation.
  Use `DateHints.wholeMinute`.
