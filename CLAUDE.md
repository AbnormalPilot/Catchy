# Catchy

Native macOS menu bar app (SwiftUI + AppKit, macOS 26+) that turns copied text or a captured
screen region into a Calendar event using Apple's on-device Foundation Models. Nothing leaves the Mac.

Goal: a 1–3 minute demo where a messy flyer becomes a correct calendar event that shows up on iPhone.

## Build & run
- Project is generated by XcodeGen from `project.yml`. After adding/removing files or changing
  settings: `xcodegen generate`. Commit both `project.yml` and `Catchy.xcodeproj`.
- Build: `xcodebuild -project Catchy.xcodeproj -scheme Catchy -configuration Debug -derivedDataPath build -allowProvisioningUpdates build`
- Test: `xcodebuild test -project Catchy.xcodeproj -scheme Catchy -derivedDataPath build -allowProvisioningUpdates`
  (Swift Testing in `CatchyTests/`, no app host; compiles the date/zone files directly). Run it after any
  change to `DateHints`, `TimeZones` or `EventExtractor`, and add a case for every date bug found.
- Run: `pkill -x Catchy; open build/Build/Products/Debug/Catchy.app`
- Quick clipboard test: `printf 'SPRING FLING\nthis saturday 7-10pm\nRiverside Park' | pbcopy` → the island opens from the notch.
- Signed with the local Apple Development identity (team 56T7M6558P). Keep a stable signature:
  ad-hoc signing changes every build and TCC (Screen Recording, Calendars) forgets the grant.

## Architecture
- `App/CatchyApp.swift` — entry point + AppDelegate wiring (status item, clipboard watcher).
- `App/StatusItemController.swift` — menu bar icon; toggles the island.
- `UI/Island.swift` — `IslandController` + non-activating `IslandPanel` above the menu bar, centred on the
  notch (`auxiliaryTopLeft/RightArea`); `IslandView` animates a `NotchShape` from notch size to content size.
  Compact (notch-height) while reading. Closes on outside click (global mouse monitor) or Esc.
- `App/AppState.swift` — `@Observable` phase machine: idle → reading → review → saved / nothingFound / failed.
- `Services/ClipboardWatcher.swift` — polls `changeCount`; uses `detectedPatterns(for: [\.calendarEvents])`
  so the contents are only read when the system says there's an event. Skips concealed/transient types.
- `Services/EventExtractor.swift` — `@Generable GeneratedEvent`, greedy sampling, fresh session per catch,
  prewarmed. Falls back to `DateHints` when Apple Intelligence is unavailable.
- `Services/DateHints.swift` — `NSDataDetector` dates/address/link; resolved dates are fed to the model as anchors.
- `Services/CalendarService.swift` — EventKit access + save; prefers an iCloud calendar so events reach iPhone/Watch.
- `Services/ModifierTapHotKey.swift` — tap ⌥⌘ (no letter key): listen-only `CGEventTap`, needs Input Monitoring;
  fires only on a quick clean tap (any key/click/⇧/⌃ in between cancels). Retries until access is granted.
- `Services/ScreenCapture.swift` — Screen Recording permission + `SCScreenshotManager.captureImage(in:)` + Vision `RecognizeTextRequest`.
- `UI/RegionSelector.swift` — dimmed overlay windows on every screen for drag-to-select.
- `Services/TimeZones.swift` — "ET"/"PST"/"GMT+1"/"London" → TimeZone.
- `Services/ServiceProvider.swift` — right-click › Services › Catch with Catchy (`NSServices` in project.yml).
- `UI/CatchListView.swift` — several catches as a checklist; `EventCardView` edits one (event or task).
- `UI/` — SwiftUI views inside the island; pitch black, dark appearance, `.island` / `.islandProminent`
  capsule button styles (user replaced Liquid Glass with a black, system-like island).

## Conventions
- Swift 6, default actor isolation = MainActor, approachable concurrency. Calling a nonisolated SDK async
  API on a non-Sendable AppKit object from MainActor errors ("sending ... risks data races"): do it in a
  `nonisolated static` helper that fetches the object itself.
- Every permission state needs visible UI: not determined → system prompt on first use; denied → banner
  with a button to the right System Settings pane.
- Keep it small. No settings screens; remember the last-used choice in UserDefaults instead.

## Lessons
- Apple Intelligence may be off on the dev Mac: `SystemLanguageModel.default.availability` is then
  `.appleIntelligenceNotEnabled` and only the `DateHints` fallback runs. Turn it on in System Settings ›
  Apple Intelligence & Siri to test the real model.
- `NSPasteboard.detectedPatterns(for: [\.calendarEvents])` (macOS 15.4+) flags casual text like
  "dinner at mine fri 8?" and flyer text; it's a reliable gate.
- `SCScreenshotManager.captureImage(in:)` takes a rect in global *display* space (top-left origin), not
  AppKit's bottom-left screen space; flip Y against the primary screen's height.
- On a notched MacBook with a crowded menu bar the status item can be hidden; the popover then anchors oddly.
- `NSDataDetector` splits "Sat, Oct 24 • 4pm - 9pm" into a date-only and a time-only match (the time
  resolves to *today*). `DateHints` merges them; strip titles using the raw phrases, not the merged one.
- User wants the hotkey as a bare ⌥⌘ tap (changed from ⌥⌘C). Carbon hot keys can't do modifier-only, hence the event tap.
- Screen Recording can't be granted from code after the first prompt, and a grant only applies after relaunch;
  the popover has "Allow Access" (prompt/opens Settings) and "Reopen Catchy".
- Test helpers that compile app files standalone: `swiftc` with a `main.swift` (top-level code) plus the
  files; don't pass `-parse-as-library`.
- With an auto-hiding menu bar the status item's window sits *above* the screen (`window.screen == nil`)
  and a popover shown from it lands in the corner. `StatusItemController` then anchors to an invisible
  window at the icon's x at the top edge. Always test auto-popups with the menu bar hidden.
- Auto-popups (copy/hotkey) need `NSApp.activate(ignoringOtherApps: true)`; plain `activate()` is refused
  under cooperative activation and the card shows dimmed/inactive.
- Don't use `onChange(of: draft.start)` to drag the end along: it also fires when a new catch replaces
  the draft. Use a custom Binding so only user edits shift the end.
- The user works on this Mac while you test; auto-popup tests steal focus. Keep live UI tests few and short.
- `NSDataDetector` already converts zoned times ("3:00 pm ET") and exposes `match.timeZone`. The model is
  told to write times *as written* plus a `timeZone`; `EventExtractor` builds the date in that zone.
- Keep `Model/`, `DateHints`, `TimeZones` free of AppKit/EventKit so they compile standalone in a
  `swiftc` harness (fast checks without launching the app).
- Verify the Services menu without clicking: `/System/Library/CoreServices/pbs -update`, then a script calling
  `NSPerformService("Catch with Catchy", pasteboard)`.
- Presenting the popover in `applicationDidFinishLaunching` does nothing; the status item isn't placed yet.
  Delay ~0.8 s (first-run welcome does this).
- The sandboxed app's defaults live in `~/Library/Containers/app.catchy.Catchy/Data/Library/Preferences/`.
- "Apple Intelligence is off" on this Mac was `appleIntelligenceNotEnabled` (M4, macOS 26.2, en-US, eligible):
  a Settings toggle, not a hardware limit. Check with a one-line script printing `SystemLanguageModel.default.availability`.
- Neither `NSDataDetector` nor the pasteboard's `detectedPatterns`/`detectedValues` understand relative times
  ("meet with sujan 20 mins", "in 2 hours", "for 15 mins"). `DateHints.relativeTimes` handles them, and the
  clipboard gate also lets chat-length text (≤280 chars) through when it has one. README's privacy note says so.
- Read lengths in context (user correction): only "in 20 mins" is a start time. A bare "20 mins" or "for 20 mins"
  is how long it lasts; with no start given, start at the next 5-minute mark. The model prompt says the same.
- `Calendar.date(bySetting: .second, value: 0, of:)` returns the *next* matching minute, not a truncation.
  Use `DateHints.wholeMinute`.
- The popover was replaced by the notch island (user request). Lessons above about popover anchoring are
  history; the island positions itself from the notch geometry instead.
- `IslandButtonStyle`'s inner view can't be named `Body`; it collides with `ButtonStyle.Body`.
- Island feel (user feedback "very big", "animation feel dropped", "smoother transition" on window switch):
  keep it ~300 pt wide with the header in the strip beside the notch; never animate `.blur` on the island
  (per-frame cost on a big view); one interruptible spring (`IslandView.spring`) for the shape;
  `.environment(\.controlActiveState, .key)` stops controls flashing grey when focus leaves.
- `.datePickerStyle(.field)` drops the stepper arrows; much tighter than `.compact` on macOS.
- No idle pill (user: "distracting", "taking the screen space"). Switching apps or clicking away hides
  the island completely; a waiting card is kept and comes back when you hover the notch. The only compact
  state is the spinner while reading (taller than the notch by 8, icons clear of it, or it looks cut).
- Hover smoothness: the island window is a fixed 400×520 transparent canvas and never resizes; only the
  black shape springs. Resizing the window mid-spring caused the stutter. Clicks pass through everything
  but the shape via `panel.ignoresMouseEvents`, updated by the 50 ms tracker. Content fades in 70 ms
  after the shape starts growing.
- Hover the notch → the island opens (50 ms dwell, no buttons held); leaving closes it after 0.25 s unless
  you clicked/typed inside (`pinned`). Driven by global + local `.mouseMoved` monitors (no permission
  needed; global misses the pointer over our own panel, local covers it) with a 0.25 s timer as backup.
  Polling every 50–80 ms plus a 0.12 s dwell felt laggy (user: "there is some delay"). Measured: fully
  open within 0.2 s on the desktop and over a full-screen app.
- Full-screen apps (VS Code, Chrome): NEVER `orderOut` the island panel. Re-ordering it in while another
  app's full-screen space is active left it undrawn, even though `isVisible`/`isOnActiveSpace` said true. Its
  size never updated, so "pointer left" closed it in a loop. The panel is ordered front once at launch and
  stays up: transparent and `ignoresMouseEvents` while closed, re-fronted on `activeSpaceDidChange`. A
  throwaway full-screen test window did NOT reproduce this; test in the real app (`open -a "Visual Studio
  Code"`, then warp the cursor).
- Because the window stays up, closing must hand keyboard focus back (`frontmostApplication.activate()`
  if the panel is key). Hover-opens don't take focus until you click in.
- When debugging the island, NSLog with a unique prefix and run the binary directly
  (`Catchy.app/Contents/MacOS/Catchy > log 2>&1 &`); remove the logs before committing. Test it by warping the cursor with
  `CGWarpMouseCursorPosition` and posting a mouseMoved, then restoring the position.
- Time zones (user: "issue with timezones"): the model may convert a time itself and leave `timeZone`
  empty, or name no zone at all. Only borrow a detector zone when that phrase's written day *and* clock time
  match the model's (`DateHints.zone(writtenAt:)`); borrowing blindly double-converted ("3pm ET" → 10:00 IST)
  and leaked one line's zone onto another event. `parseTime` must accept "3:00 PM"/"3pm"/"9.30" too;
  strict "HH:mm" silently made events all-day.
- "PST"/"EST" written in summer mean the region's local time (America/Los_Angeles), not a fixed offset,
  same as Google Calendar. Deliberate.
- EventKit does NOT apply a calendar's default alerts to events created by apps, so saved events had no
  Calendar notification. `CalendarService.alert` (default 15 min, remembered) adds an `EKAlarm`; all-day
  events use 9 AM on the day / day before. Each save also posts a `UNUserNotificationCenter` notification
  (`Notifier`) with Undo/Open actions. Its delegate methods are `nonisolated` and hop to MainActor.
- Calendar never fires an alert whose time has already passed when the event is saved. "15 min before"
  on a "meet in 10 mins" event was silent (user: "didnt got any notification"). `EventAlert.effective`
  falls back to "at start" (none if already started); the bell chip shows the effective alert.
- Generic icon in Notifications settings = stale LaunchServices/icon cache, not a missing icon (the built app
  has AppIcon.icns). Every extra build of Catchy.app (e.g. a fresh-clone test build in the scratchpad)
  registers another copy. After such a build run `lsregister -u <that copy>`. To refresh: `touch` the app,
  `lsregister -f` it, `killall NotificationCenter usernoted`, then reopen System Settings.
- Notification settings only list the kinds an app asks for. `Notifier.kinds` = alert + sound + badge,
  re-requested at launch so an existing grant picks up new kinds. "Time Sensitive" needs the
  `com.apple.developer.usernotifications.time-sensitive` entitlement; `-allowProvisioningUpdates` made a
  Mac team profile for it automatically, and TCC grants (Calendar etc.) survived the re-sign.
- Voice: `SpeechAnalyzer` + `SpeechTranscriber` (macOS 26) is fully on-device; first use downloads the model
  via `AssetInventory`. The AVAudioEngine tap runs on a real-time thread: keep it in a `nonisolated`
  @unchecked Sendable helper (`AudioFeed`); a MainActor closure there would trip Swift 6's isolation check.
  Test without a mic: `say -o x.aiff "…"` then `analyzer.analyzeSequence(from: AVAudioFile)`.
- Speech comes out as "5.30" and "at one"; neither Apple detector reads those. `TextCleanup.normalized`
  runs on every extraction. Add a test in `CatchyTests/SpokenTests.swift` for each new phrasing.
- Esc: the capture overlay only got Esc if Catchy was the active app, and macOS can refuse `activate()`
  when the ⌥⌘ tap fires from another app. `RegionSelector` now force-activates, and the hotkey's event
  tap reports Esc (keycode 53) to `AppState.escapePressed()` as a backup (overlay or dictation only; other
  apps keep their Esc). Test: post flagsChanged ⌘ then ⌘⌥ then none, screenshot, post Esc, screenshot.
- Voice edits: `DateHints` adds a stand-in start (empty phrase) for a bare length; ignore it when editing,
  or "for 2 hours" moves the event instead of lengthening it. Tests in `CatchyTests/VoiceEditTests.swift`.
